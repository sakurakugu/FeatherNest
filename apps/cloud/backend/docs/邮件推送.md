# 邮件推送

邮件是推送管理中的一种渠道，通过 Resend HTTP API 发送。Cloudflare Email Routing 继续负责接收和转发，无需调整现有 DNS 或开启 Resend 接收。

## 配置渠道

打开后台“推送管理 → 推送渠道 → 新增渠道”，选择“邮件（Resend）”，填写：

- Resend API Key：建议使用限制到已验证域名的发送权限密钥。
- 发件地址：例如 `FeatherNest <noreply@sakurakugu.com>`，域名必须在 Resend 验证。
- 收件地址：一个或多个邮箱，用英文逗号分隔，最多 50 个。
- 回复地址：可选，可填写已经通过 Cloudflare 转发的邮箱；未设置时回复到发件地址。

配置沿用推送渠道的加密存储，不回显密钥。编辑时只更新填写的字段，留空保留旧值。创建后点击渠道“测试”验证发送。接口返回成功表示 Resend 已受理，实际投递情况请检查收件箱与 Resend 发送日志。多个收件人可能互相看到地址，需要隔离时应分别创建渠道。

邮件无需配置额外环境变量，也不提供独立的系统设置发送入口。已在环境变量中填写的 `RESEND_API_KEY`、`MAIL_FROM`、`MAIL_REPLY_TO`、`MAIL_TIMEOUT_SECONDS` 不再被读取，应在渠道中重新填写。

## 使用渠道

邮件渠道可绑定到推送令牌，并作为友链每日汇总的推送渠道。调用方式与其他渠道相同，使用 `POST /api/v1/notifications/send`，在请求头传入 `Authorization: Bearer <推送令牌>`。

```json
{
  "title": "任务完成",
  "content": "脚本已执行完成。",
  "content_type": "text"
}
```

邮件标题使用推送标题。纯文本直接发送；Markdown 转换成 HTML；HTML 保留原正文，同时生成纯文本版本。

服务不自动重试，每次推送调用生成独立的邮件幂等键。超时意味着结果未确定；重新调用推送接口会创建新的发送请求，应先在 Resend 日志确认是否已受理，避免重复邮件。

日志记录邮件编号、收件人数、上游状态码与网络异常类型，不记录 API Key、收件地址或正文。渠道表已支持字符串类型的平台标识与加密配置，无需数据库迁移。MCP 保持原有能力，不新增独立邮件工具。
